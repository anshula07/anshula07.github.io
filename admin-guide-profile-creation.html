Writing Sample — Admin Guide

Creating Access Profiles in SentraGuard EPM

A step-by-step admin guide for configuring endpoint privilege profiles

About this sample: SentraGuard is a fictional Endpoint Privilege Management (EPM) product created for portfolio purposes. It represents the type of admin-facing documentation I write in my current role — clear, task-oriented guides for cybersecurity administrators — without using any real product, client, or company content.

1. What is an Access Profile?

An Access Profile in SentraGuard defines what a user or group of users is allowed to run, install, or elevate on their endpoint. Instead of granting broad local administrator rights, admins build a profile that lists exactly which applications and processes are permitted, restricted, or allowed to run with elevated privileges — and then assign that profile to the right users, groups, or machines.

Profiles can be built manually, one rule at a time, or generated automatically from a device's recent activity history, which is useful when you want a starting point based on what a user already runs day to day.

2. Why Access Profiles Matter

  • Reduces standing admin rights — users get only the specific privileges they need, not full local admin access.
  • Keeps policy consistent — one profile can be reused across an entire team or department instead of configuring each machine separately.
  • Speeds up audits — because rules live in one place, security teams can review exactly what's permitted without checking individual endpoints.
  • Adapts as teams change — profiles can be edited centrally, and the update applies everywhere the profile is assigned.

3. Before You Start

You'll need Profile Administrator permissions in SentraGuard, and you should know which department or business unit (referred to as a Team Scope) the profile applies to. A profile can only be created under a single Team Scope — it cannot span "All Teams."

4. Creating a New Profile

  1. From the left navigation menu, go to Access > Profiles.
  2. Select the correct Team Scope from the dropdown at the top of the page.
  3. Click + New Profile in the upper right corner.
  4. Fill in the profile details (see the field reference table below), then click Continue.

Profile Setup Fields

FieldDescription
Profile NameA short, identifiable name for the profile, e.g. "Finance Team – Standard Access."
DescriptionA brief note on who this profile is for and what it restricts, for future reference.
Operating SystemWindows, macOS, or Linux. Each profile applies to one OS type.
Set as DefaultWhen enabled, this profile is automatically applied to any new device enrolled under the selected Team Scope. Only one default profile is allowed per OS type.
Time-Limited AccessWhen enabled, grants temporary elevated rights that automatically expire after a set duration, rather than persisting indefinitely.
Auto-Suggest RulesWhen enabled, SentraGuard scans recent activity on assigned endpoints and suggests commonly used applications to pre-populate the profile.
Enabling Set as Default and Auto-Suggest Rules at the same time isn't supported — turning one on automatically disables the other, since a default profile is meant to apply a fixed baseline rather than one built from variable usage data.

5. Adding Rules to the Profile

Once the profile shell is created, you'll define what it actually allows or blocks:

  1. Open the profile and select Add Rule.
  2. Choose a rule type: Allow, Block, or Elevate.
  3. Search for the application by name, or paste in its file hash for an exact match.
  4. Click Save Rule. Repeat for each application you want to control.
[Screenshot placeholder: rule list showing Allow / Block / Elevate tags]

If You Used Auto-Suggest Rules

Instead of adding applications one at a time, review the suggested list SentraGuard generated from endpoint activity. Each suggested application shows how many users or devices ran it recently. Select the ones you want to approve, choose whether to allow them as-is or elevate them, and click Apply Selected.

6. Assigning the Profile

  1. From the Profiles list, click the Assign icon next to the profile you created.
  2. Choose who the profile applies to: individual users, a user group, specific devices, or a device group.
  3. Set the assignment as Permanent or Scheduled (with a start and end date).
  4. Click Save Assignment.
A device or user can only have one active profile per OS type at a time. Assigning a new profile automatically replaces the previous one for that device or user — it doesn't stack on top of it.

7. Confirming It Worked

After saving an assignment, SentraGuard displays a confirmation banner and updates the profile's Assigned To column on the main Profiles list. To double-check a specific device picked up the new rules, go to Devices > [device name] > Active Profile and confirm the profile name and last sync time match what you expect.

Summary

Access Profiles let administrators centralize privilege management instead of configuring permissions device by device. Getting the setup right — the correct Team Scope, a clear default vs. auto-suggested baseline, and a deliberate assignment scope — keeps privilege creep low and makes future audits far easier to run.
