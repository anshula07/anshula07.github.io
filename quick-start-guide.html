Quick Start Guide

Get Started with Sentinel Privilege Manager

Follow this guide to quickly configure Sentinel Privilege Manager, register your first endpoint, create a privilege policy, and verify controlled application elevation.

Product: Sentinel Privilege Manager Version: 3.2 Time: 15–20 minutes Audience: Administrators

1. Overview

Sentinel Privilege Manager (SPM) is a fictional Endpoint Privilege Management platform that enables organizations to control elevated privileges across managed endpoints.

This Quick Start Guide provides the minimum steps required to configure a basic SPM environment and validate application elevation.

Who should use this guide? Use this guide if you are setting up Sentinel Privilege Manager for the first time or want to quickly validate the core privilege management workflow.

2. Prerequisites

Make sure the following requirements are available before starting the configuration.

Administrator Access

You must have administrative credentials for the SPM management console.

Supported Endpoint

A supported Windows, macOS, or Linux endpoint is required for testing.

Network Connectivity

The endpoint must be able to communicate with the SPM management service.

Endpoint Agent

The SPM endpoint agent must be installed on the device being managed.

3. Access the SPM Console

1

Open the Console

Open a supported web browser and navigate to the Sentinel Privilege Manager console URL provided by your organization.

2

Enter Credentials

Enter your administrator username and password.

3

Sign In

Click Sign In to access the administration dashboard.

Expected Result The SPM Dashboard is displayed after successful authentication.

4. Register an Endpoint

The endpoint agent allows a device to communicate with the SPM management service.

1

Open Endpoints

From the navigation menu, select Endpoints.

2

Verify Agent Status

Confirm that the SPM agent is installed and running on the target endpoint.

3

Verify Endpoint Registration

Confirm that the endpoint appears in the managed endpoint list.

Expected Result The endpoint appears in the SPM console with an active or healthy status.

5. Create Your First Privilege Policy

Create a simple policy that allows a selected application to run with controlled elevated privileges.

1

Open Privilege Policies

Navigate to Policies → Privilege Policies.

2

Create a Policy

Click Create Policy.

3

Enter Policy Details

Enter a unique policy name and description.

4

Define the Application

Specify the application that should receive controlled elevation.

5

Select the Target

Select the required user, user group, endpoint, or endpoint group.

6

Save the Policy

Click Save to create the privilege policy.

6. Test Application Elevation

After creating the policy, test the configured application from the target endpoint.

1

Sign in to the Endpoint

Sign in using a user account targeted by the privilege policy.

2

Launch the Application

Open the application specified in the privilege policy.

3

Verify Elevation

Confirm that the application receives the configured elevated privileges.

Expected Result The approved application launches successfully with the privileges defined by the policy.

7. Verify Activity

SPM records privilege-related activity for monitoring and auditing.

1

Open Activity

Navigate to the activity or audit section of the SPM console.

2

Search for the Endpoint

Filter the activity records using the endpoint or user name.

3

Review the Event

Verify that the application elevation event has been recorded.

8. Quick Validation Checklist

Use this checklist to confirm that the basic configuration is working.

  • Administrator can access the SPM console.
  • Endpoint agent is installed and running.
  • Endpoint appears in the SPM console.
  • Privilege policy has been created.
  • Policy has been assigned to the correct target.
  • Approved application launches successfully.
  • Application elevation activity is recorded.
Setup Complete Your basic Sentinel Privilege Manager environment is now configured and ready for further policy configuration.

9. Common Issues

Issue Possible Cause Action
Endpoint is not visible Agent is not communicating with the management service. Verify agent status and network connectivity.
Policy is not applied Policy target does not match the user or endpoint. Review the policy assignment.
Application does not elevate Application conditions may not match the policy. Review the application configuration and policy conditions.
Activity is not visible Event processing or endpoint communication may be delayed. Verify endpoint connectivity and review the latest check-in.

10. What's Next?

After completing the Quick Start configuration, administrators can continue with advanced configuration and management activities.

Create User Groups

Organize users for centralized policy assignment.

Configure Advanced Policies

Define application, user, and endpoint-specific privilege rules.

Review Reports

Analyze privilege activity and policy events.
